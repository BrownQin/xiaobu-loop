# 小步 · AI 智能测评演进方案

**版本**：v1（对应 App v0.11.0）
**日期**：2026-11-13
**结论先行**：大模型不进入「判分 + 选题」链路；它的价值在「解释为什么」和「生成下一层内容」。v0.11 先把证据链补齐，不写一行模型代码。

---

## 一、边界：谁负责什么

测评要可信，必须满足三个前提：同一份作答在任何设备上算出的结果一致、结论可解释、错了可复现。三者大模型都不保证。

| 环节 | 承担者 | 理由 |
| --- | --- | --- |
| 判分 | 本地规则 `AnswerJudge` | 可复现、零成本、无幻觉 |
| 选题 | 本地 BKT + 最近发展区 | 数学可验证，3 题内可解释 |
| 掌握状态 | `AnchorBktEngine` | 参数可调、可回溯 |
| 归因（为什么错） | 大模型（v0.13） | 规则写不出「把退位当成直接减」 |
| 讲一遍判分 | 语音识别 + 大模型（v0.12） | 规则根本做不到 |
| 变式题生成 | 大模型离线批处理 + 人工审核（v0.14） | 扩容边际成本最低 |
| 家长话术 | 大模型（v0.13） | 家长真正会用的产出 |

一句话：**确定性内核负责「测准」，模型负责「说清」和「造新题」。**

## 二、证据模型

### 2.1 已有的证据（v0.11）

`learning_record` 每次作答一行：

| 字段 | 含义 | 用途 |
| --- | --- | --- |
| `anchor_code` / `cognitive_level` | 该题属于哪个锚点的哪一层 | 聚合出锚点 × 层级证据 |
| `is_correct` | 判分结果 | 正确率 |
| `duration_ms` | 作答耗时 | 与孩子自身基线比较，识别秒答 / 犹豫 |
| `signal_quality` | NORMAL / FAST_SUSPECT / HESITANT | 判断「对得可不可信」 |
| `option_switches` | 选择题切换选项次数 | 切换多 = 不确定 = 可能猜对 |
| `answer_changes` | 填空题改答次数 | 反复改 = 掌握不稳 |
| `timestamp` | 作答时间 | 遗忘曲线、干预前后对比 |

`anchor_state` 每个锚点 × 层级一行：`probability`、`confidence`、`status`、`attempts`、`correct`。

### 2.2 待补的证据（v0.12 起）

| 证据 | 采集方式 | 支撑的功能 |
| --- | --- | --- |
| 表达（讲一遍） | 录音 → 系统离线语音识别 → 文本 | 理解层判分、归因 |
| 干预记录 | 家长在面板记一笔「今晚讲了退位」 | 哪种干预对哪个孩子有效 |
| 变式对比 | 同锚点不同 `variant_type` 的正确率 | 判断是「没懂」还是「只认一种问法」 |
| 退出与放弃 | 中途返回、超时未答 | 挫败信号，用于调整题量 |

## 三、证据怎么用

这是本方案的核心：**每一项证据都必须对应一个明确的判定或一个明确的产出**，否则不采集。

| 证据组合 | 判定 | 触发动作 | 使用版本 |
| --- | --- | --- | --- |
| 正确率 ≥ 95%，样本 ≥ 3 | 题目偏简单 | 提示上调层级或降频 | v0.11（已上线） |
| 正确率 ≤ 25%，样本 ≥ 3 | 题目偏难或标错 | 提示先核对题干与答案 | v0.11（已上线） |
| 秒答占比 ≥ 50% | 疑似背答案 / 选项可排除 | 换问法再验证一次，不扣星 | v0.11（已上线） |
| 答对 + 切换 ≥ 2 次 | 「不稳定地对」 | 置信度降为 LOW，不进 SOLID | v0.12 |
| 讲一遍缺失关键概念 | 记忆过了、理解没过 | 理解层维持攻坚中，给家长一句提示 | v0.12 |
| 同一锚点换表征后正确率骤降 | 只会一种问法 | 增加该变式的题量 | v0.12 |
| 干预后 3 天内状态提升 | 该干预对这个孩子有效 | 下次优先推荐同类干预 | v0.13 |
| 连续 2 次超时或退出 | 挫败 | 明日题量降到 2 题或下沉一层 | v0.13 |

### 3.1 给大模型的输入：证据包，而不是原始数据

不要把所有记录丢进 prompt。压成一条结构化摘要（≤ 800 token）：

```json
{
  "child": {"stage": "PRIMARY_LOW", "grade": "二年级"},
  "anchor": {"code": "math-sub-borrow", "name": "退位减法的算理"},
  "states": [
    {"level": "MEMORY", "status": "SOLID", "p": 0.91, "attempts": 6},
    {"level": "UNDERSTANDING", "status": "IN_PROGRESS", "p": 0.48, "attempts": 4}
  ],
  "recent": [
    {"q": "53-27", "ans": "24", "ok": false, "dur": 21, "sig": "HESITANT", "switches": 2},
    {"q": "42-18", "ans": "24", "ok": false, "dur": 17, "sig": "NORMAL", "switches": 1},
    {"q": "50-20", "ans": "30", "ok": true, "dur": 8, "sig": "NORMAL", "switches": 0}
  ]
}
```

### 3.2 模型输出：限定枚举 + 可验证动作

```json
{
  "hypothesis": "把退位理解成直接减，未把借走的十还回去",
  "evidence": ["53-27 得 24", "42-18 也得 24"],
  "verify": "让他口算 42-18，并说出个位不够减时怎么处理",
  "script": "你把个位借走的那 1 个十，还回去了吗？",
  "confidence": "MEDIUM"
}
```

关键约束：模型给的不是结论，而是一个**可执行的验证动作**。孩子做一次就能证伪，错误判断不会污染掌握度。

## 四、演进路线

### v0.11 证据链（本版，已完成）

- `learning_record` 增加 `option_switches`、`answer_changes`；DB v6 → v7
- 新增「题目质量」看板：偏简单 / 偏难或标错 / 疑似秒答 三类提示
- 备份补全：学段、锚点、层级、信号质量、过程信号全部可导出恢复
- 不调用任何模型

验收：一周试用后，能在看板里指出至少 3 道「判据成立」的题目，并与家长主观感受一致。

### v0.12 讲一遍

- 理解层加入语音作答：录音 → 系统离线识别 → 规则 + 模型双判
- 不一致时判为「待观察」，不直接改状态
- 模型超时 3 秒自动降级回选择题
- 答对但多次切换选项 → 置信度降级

验收：家长能看到孩子原话摘录与缺失的关键概念；模型不可用时功能不阻塞。

### v0.13 归因与教练剧本

- 周报从统计数字升级为：一个假设 + 一个验证动作 + 一段今晚就能说的话
- 所有结论带证据引用，可点回具体题目
- 新增干预记录，形成「干预 → 效果」对照

验收：家长按建议执行一次后的状态提升比例，高于无建议组。

### v0.14 生成式题库

- 家长点「为这个锚点生成 5 道变式」→ 后台批量生成 → 待审核队列 → 确认后入题库
- 复用现有 CSV 通道，架构零改动

验收：新题上线 3 天内，正确率落在 35%–85% 区间的比例。

### 再往后

多锚点学习路径规划。需要足够答题量支撑，当前做属于拍脑袋。

---

## 五、工程约束

- 做题链路零模型调用；只在报告、归因、批量生成时调用
- 每次调用都有模板兜底，超时 3 秒回退，不向用户报错
- 输入做证据压缩，聚合到 5–10 条代表样本，token 相差约 20 倍
- 输出强制 JSON schema + 枚举，解析失败直接走兜底，不做「让模型重试」
- 缓存键 = 锚点 + 层级 + 状态哈希，同一状态 7 天内不重复生成
- 隐私：语音优先用系统离线识别；上传前去除姓名，只保留 `child_id`

## 六、一周试用要观察什么

> 数据怎么导出、怎么读、怎么下结论，见《诊断日志：导出、读取与分析方法》（DIAGNOSTICS.md）。本节只列观察项，具体阈值与判读步骤在那边。

1. 每天是否有人真的做完 3 题（完成率）
2. 「题目质量」里出现偏简单 / 偏难的题目数量与具体内容
3. 是否出现「答对但切换多次」的题（说明存在侥幸对）
4. 家长是否点开锚点矩阵（说明结论是否有用）
5. 家长有没有主动问「那今晚我该做什么」——这是 v0.13 的需求验证

前两项决定题库质量，后三项决定下一版做归因还是做教练剧本。

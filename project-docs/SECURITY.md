# 小步安全说明（SECURITY）

- 适用版本：0.16.0 及以上
- 维护者：小步个人开发者
- 问题反馈：GitHub Issues（<https://github.com/BrownQin/xiaobu-loop/issues>）

本文说明小步的威胁模型、已采取的防护措施，以及分发/上架前必须遵守的操作规范。

---

## 一、资产与威胁模型

| 资产 | 风险 | 当前处置 |
|---|---|---|
| 题库与判分/推荐算法 | 反编译后可直接复制 | release 开启 R8 混淆 + 资源裁剪；`mapping.txt` 不公开 |
| 统计 Webhook 地址 | 打包进 APK，可被反编译提取并伪造上报 | 端点只允许 HTTPS；接收端只接受 6 个白名单字段；不包含任何个人身份信息；可随时轮换 |
| 签名密钥 | 泄露后可被冒名发布更新 | keystore 存放在仓库之外，`keystore.properties`、`*.jks` 已加入 `.gitignore` |
| 本地学习数据 | 设备丢失、被其他 App 读取 | 仅存于应用私有目录；关闭云备份与设备迁移；不申请存储/通讯录等权限 |
| 开发者个人信息 | 被写入 APK 或仓库，遭爬取骚扰 | 代码与文档不写入手机号、私人邮箱、住址；对外只保留公开 Issues 入口 |

### 明确不在防护范围内

- 已 root/越狱设备上的内存抓取与动态调试；
- 攻击者直接拿到已签名 APK 后的静态分析（混淆只能提高成本，不能绝对阻止）；
- 用户主动导出并分享的备份文件、诊断日志。

## 二、Webhook 的安全设计

### 2.1 现状

- 端点通过 `-PtelemetryWebhook=` 在构建时注入，默认值为空字符串；
- 未传参时 `BuildConfig.TELEMETRY_WEBHOOK` 为空，App 完全不发送；
- Gradle 构建期校验：只接受 `https://` 开头的地址，防止明文传输；
- 上报内容固定为 6 个字段，接收端按字段白名单写入，不接受任意 JSON；
- App 侧不携带任何密钥、Token、个人邮箱。

### 2.2 已知残余风险

Webhook URL 一旦打进 APK，就可能被提取。拿到 URL 的人可以伪造事件，导致统计被污染，但**无法读取任何用户数据**（接收端只写不读，且 App 不发送身份信息）。因此评估结论是：可接受用于「事件级匿名统计」，不用于任何敏感业务。

### 2.3 推荐的中继方案（流量变大或出现伪造时启用）

1. 部署一个无状态中继（Cloudflare Worker / 云函数均可），APK 只内置中继地址；
2. 中继做三件事：校验字段白名单、按 `install_id` 限流（如每 IP 每分钟 30 次）、丢弃多余字段；
3. 中继再转发到飞书多维表格 Webhook，飞书地址不进入 APK；
4. 如需进一步防伪，可在中继校验 App 签名证书哈希（仅提高门槛，不是强认证）。

### 2.4 轮换与止损

- 怀疑被滥用时，直接在飞书多维表格中禁用旧自动化并生成新 Webhook；
- 重新发版注入新地址即可，旧安装最多影响统计完整性，不影响功能；
- 不因统计问题要求用户升级，避免打扰。

## 三、发布与密钥管理规范

1. `keystore.properties` 与 `*.jks` **只保存在开发者本机/密码管理器**，绝不提交到 Git；
2. 每次 release 构建后保留 `app/build/outputs/mapping/release/mapping.txt`，仅私下留存，用于解读崩溃堆栈；
3. 发布前检查仓库不含个人信息与密钥：

   ```bash
   # 在仓库根目录执行
   git grep -nE "(hook/|api[_-]?key|secret|token|BEGIN .*PRIVATE KEY)" -- . ':!*.lock'
   git grep -nE "([A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,})" -- . ':!*.lock'
   ```

4. 只从 release 产物分发，不再分发 debug APK（debug 包可被调试、体积更大、包含调试符号）；
5. 应用市场要求提供开发者联系方式时，使用专门的工作邮箱/公开主页，不要使用私人手机号。

## 四、漏洞报告

请通过 GitHub Issues 私下联系维护者（不要在公开 Issue 中粘贴可利用细节）。确认后会在下个版本修复，并在 `CHANGELOG.md` 中说明影响范围。
